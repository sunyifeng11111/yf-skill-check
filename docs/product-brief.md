# Skill 触发冲突体检：需求记录

## 用户目标

制作一个可安装的 skill，检查技能过多造成的触发冲突及潜在 Token 浪费，生成 HTML 网页体检报告。

## 已确认的决定

- 体检 skill 从哪个平台调用，就检测哪个平台；使用该平台的技能目录与发现规则，不默认混扫其他平台。
- 先筛查冲突候选，再由执行体检的当前模型结合技能正文复核。
- 报告附共同触发示例、冲突依据和分工建议。
- 第一版估算常驻目录成本和误加载正文的情景成本，清楚标注估算。
- 读取历史会话逐条核算不在第一版范围内。
- 第一版只体检和给建议，不自动修改、合并、卸载或禁用已安装技能。
- 加入重复安装、触发描述过宽、正文过长且缺少按需加载、失效引用、读取或解析失败的检查。
- 交付本地可直接打开的中文交互 HTML，支持筛选问题、展开证据和查看各 skill 的成本。

## 已核实的事实与推论

- Codex 技能采用渐进加载：先提供技能目录，选中后读取正文。全部已安装技能正文的 Token 合计不能作为每轮实际浪费。
- 目录存在不代表技能一定已启用或被当前模型发现；报告应区分可发现范围和文件存在范围。
- 多个目录入口可能指向同一个真实文件。扫描应保留来源信息，并避免把同一文件重复计为不同技能。
- 语义相似不足以确认冲突：显式调用限制、前置条件、平台分流、版本兼容边界和流程依赖均可能解释重叠。

来源：Codex 官方 [Build skills](https://learn.chatgpt.com/docs/build-skills)，以及本机技能目录与版本技能的只读核查。以上平台行为只用于 Codex；其他平台需要各自核实。

## 平台识别约束

- 当前平台优先由会话明确身份或宿主运行上下文识别。安装路径、已安装 CLI 和目录存在只能作为辅助证据。
- 多平台可能共享 `.agents/skills`；Cursor 还兼容 Claude 和 Codex 的技能目录。因此，体检 skill 所在目录不能单独证明当前调用平台。
- 扫描应使用当前平台实际发现规则；兼容目录仍属于当前平台的扫描范围。
- Codex、Claude Code 对同名技能的处理不同。应按平台解释覆盖或并存，不能把同名一律当成重复加载。
- 插件、内置或同步技能可能没有可读本地文件；报告说明可见但不可读的来源及覆盖缺口。
- 远程或容器会话检查当前执行环境，不自动使用用户桌面上的其他环境。
- 无法可靠识别的平台应标为未验证，不能把多个平台混扫后当作当前平台结果。

核实来源：[Codex Build skills](https://learn.chatgpt.com/docs/build-skills)、[Claude Code Skills](https://code.claude.com/docs/en/skills)、[Cursor Agent Skills](https://cursor.com/docs/skills)。这些约束是设计依据，不代表用户已选择全部平台作为第一版适配范围。

## 实现边界

- 当前模型复核，不额外要求模型 API Key 或第三方服务。
- 优先按已核实的 Codex、Claude Code、Cursor 规则发现目录；其他宿主由执行模型提供其实际技能根目录，标注适配未验证。
- 宿主身份不清楚时询问平台，不以安装目录猜测。
- 技能依赖 Python 3 标准库完成基础扫描和报告生成；可选 tokenizer 用于更精确地计数，默认使用明确标注的字符估算。
- 不添加按轮自动体检、历史日志读取或费用核算。

## Token 展示约束

每项数字说明计数方法、适用平台、扫描覆盖范围与是否实测。正文长度是触发后的潜在加载成本，不代表自动浪费；引用文件也不能默认全部加载。估算上下文占用不直接转换成实际账单。

## 报告体验修订（2026-10-10）

报告帮助用户决定是否调整及先调整什么。首页展示一句结论、最多三条优先建议和 Token 概览；疑点、模拟及完整原文按需展开。完整明细保留正常分工和全部记录。

长度、没有 Markdown 文件链接、简介范围和同名来源只作为配置信息。重复内容和缺失链接默认可以留意，需模型判断实际用途与影响。优先建议要求明确同一条件下的矛盾，或具体使用情景、影响与真实原文。读取失败只记为检查限制。允许合理的综合职责、完整工作流、不同风格与阶段协作；不采用健康评分、不为凑建议升级疑点。
